Cursor plugin v0.6.1 packages the opt-in tool-loop policy and checkpoint-lineage optimizations. The native plugin ABI remains unchanged.

## Changes

- Add the optional account-auth JSON field `tool_loop_guard_tools`. Missing, null or empty lists do not hard-stop any tool. Tool names match exactly and case-sensitively; chat payloads cannot override the account policy, and OAuth refresh preserves it.
- For explicitly selected tools only, three adjacent, unambiguously linked single-call/result exchanges with identical names, arguments and nonempty results can stop before another upstream request. Streaming and non-streaming entrypoints return `cursor_tool_loop_detected` with an HTTP 400 hint and a non-retryable error envelope.
- Treat equivalent adjacent text chunks consistently when matching checkpoint history, while preserving whitespace, media boundaries, tool identities, history order and account/model/session isolation.
- Append assistant-history digests incrementally instead of rehashing the entire transcript.

## Compatibility and upgrade

- Existing credentials and OpenCode sessions require no migration. Upgrading does not enable tool-loop policy, rewrite saved conversations or change model-disable settings.
- Do not opt polling tools or cumulative side-effect tools into the guard unless repeated identical results should stop that workflow. The guard can also prevent a final summary after the selected pattern; a new user message or removing the tool from the policy allows continuation.
- This is a bounded heuristic, not a complete loop-prevention or cost-limit guarantee. Multi-tool batches and interrupted or rewritten history can fall outside its detection shape. Cache improvements do not deduplicate or skip actual tool execution, and do not establish upstream billing savings.
- `cursor_0.6.1_linux_amd64.zip` is the plugin-store package; its root contains only `cursor.so`. `cursor-plugin-0.6.1-linux-amd64.tar.gz` includes the manual installer, documentation and binary checksum. Verify package hashes against the accompanying `checksums.txt`.
- The installer retains the previous binary in `.cursor-backups/`. Restart CLIProxyAPI only when actually installing a new binary; in-memory checkpoints are rebuilt. A source-version commit or package build alone does not upgrade a running service.

## Validation scope

Regression coverage includes default-policy continuation, exact opt-in matching, credential round-trip/refresh, streaming and non-streaming rejection, call/result association, changed arguments/results, user continuation, adjacent-text equivalence and incremental-digest parity. CI runs the full Go race/shuffle suite and vet before Linux shared-library packaging.

Synthetic test and ABI acceptance do not prove that every real OpenCode conversation is free of repeated operations, and do not constitute Cursor service-side billing verification. See the [behavior and acceptance notes](../cursor-tool-loop-and-cache.md) for the precise limits.

This is an unofficial community plugin for user-authorized Cursor accounts. Review the bundled `DISCLAIMER.md` before installation.
