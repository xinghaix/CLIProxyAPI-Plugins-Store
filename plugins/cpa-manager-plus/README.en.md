# CPA Manager Plus (CPA Plugin)

[中文](README.md) | English

`cpa-manager-plus` adds a sidebar menu item named "CPA Manager Plus" to the CPA management UI. The page uses tabs for dashboard, usage analytics, request monitoring, account inspection, settings, and health checks, and proxies server-side calls to [CPA-Manager-Plus](https://github.com/seakee/CPA-Manager-Plus) Manager Server. The default Manager Server URL is `http://127.0.0.1:18317`.

## Current architecture decision

This plugin does not proxy, iframe, or embed the full Plus `management.html` page.

Reason: Plus is an independent management product. Embedding the full console inside a CPA plugin page would mix visual design, routing, login state, and layout boundaries with CPA Management Center.

Correct boundary:

1. The frontend belongs to the plugin
   - The plugin resource page is a CPA-style single-page app.
   - Current required tabs are migrated/rewritten: overview, usage analytics, request monitoring, account inspection, settings, and health.
   - Styling uses CPA Management Center CSS variables such as `--bg-secondary`, `--bg-primary`, `--text-primary`, `--border-color`, and `--primary-color`.

2. Backend data still comes from Manager Server
   - SQLite, collectors, historical usage, and Codex server inspection remain owned by Manager Server.
   - The plugin does not inline those backend modules.

3. The plugin only reverse-proxies required APIs
   - The browser talks only to same-origin CPA on port `8317`.
   - The plugin server calls Manager Server through `host.http.do`, defaulting to port `18317`.
   - Only Manager API paths required by plugin tabs are allowed; this is not a generic HTTP tunnel.

## Architecture

```text
CPA Management Center
    │
    ▼
/v0/resource/plugins/cpa-manager-plus/app
    │
    ▼
Vue single-page plugin UI
    │
    ▼
/v0/management/cpa-manager-plus/proxy
    │
    ▼
CPA plugin server handler
    │ host.http.do
    ▼
CPA-Manager-Plus Manager Server
    default: http://127.0.0.1:18317
```

## Frontend build architecture

The plugin uses `web/` + Vite + Vue SFC instead of loading a runtime Vue CDN/global build directly from `index.html`:

```text
plugins/cpa-manager-plus/
├── web/
│   ├── package.json
│   ├── package-lock.json
│   ├── vite.config.js
│   └── src/
└── go/
    ├── embed.go
    ├── main.go
    └── web-dist/      # Vite output, git ignored, generated by make/CI
```

Build command:

```bash
cd plugins/cpa-manager-plus
make build
```

`make build` runs:

```bash
cd web && npm ci && npm run build
cd go && go mod tidy
cd go && CGO_ENABLED=1 go build -buildmode=c-shared -o ../cpa-manager-plus-v<version>.dylib .
```

Go embeds the compiled `go/web-dist` through `embed.FS`. Do not pass unbuilt frontend source or a runtime CDN page directly to Go embed.

## URL structure

| Feature | Path | Notes |
|---------|------|-------|
| Plugin page | `GET /v0/resource/plugins/cpa-manager-plus/app` | Resource route, no CPA management middleware |
| Health check | `GET /v0/management/cpa-manager-plus/health` | CPA management auth |
| API gateway | `POST /v0/management/cpa-manager-plus/proxy` | CPA management auth, proxied to Manager Server |

Proxy request body:

```json
{
  "method": "GET",
  "path": "/v0/management/dashboard/summary",
  "query": "today_start_ms=1710000000000"
}
```

`path` is the path on Manager Server. The plugin validates both path and method through an allowlist.

## Configuration: `plugins.configs.cpa-manager-plus`

| Field | Description |
|-------|-------------|
| `manager_base_url` | Manager Server URL, default `http://127.0.0.1:18317` |
| `management_key` | Optional Plus Manager admin bearer. Used only by the plugin server when calling `18317`. Omit for local Manager Server without auth. Legacy field `admin_key` is still accepted and equivalent to `management_key`. |

Do not put the CPA management key (`remote-management.secret-key`) in plugin config. Browser calls to `/v0/management/cpa-manager-plus/*` need CPA management login state or the temporary key entered in the plugin page; the plugin process cannot read CPA's secret-key through the SDK.

`management_key` and CPA secret-key are different:

- CPA secret-key: used by the browser to access CPA `/v0/management/*`.
- Plus `management_key`: used by the plugin server to access Manager Server `18317`.

## Installation

### Recommended: CPA v7.2.46+ with CDN v2 registry

```yaml
plugins:
  enabled: true
  store-sources:
    - "https://cdn.jsdelivr.net/gh/xinghaix/CLIProxyAPI-Plugins-Store@cdn/registry-v2.json"
```

### GitHub raw fallback

```yaml
plugins:
  enabled: true
  store-sources:
    - "https://raw.githubusercontent.com/xinghaix/CLIProxyAPI-Plugins-Store/main/registry-v2.json"
```

### Older CPA compatibility entry point

```yaml
plugins:
  enabled: true
  store-sources:
    - "https://raw.githubusercontent.com/xinghaix/CLIProxyAPI-Plugins-Store/main/registry.json"
```

Install:

```bash
curl -X POST http://localhost:8317/v0/management/plugin-store/cpa-manager-plus/install \
  -H "Authorization: Bearer ***"
```

Enable and configure Manager Server:

```yaml
plugins:
  enabled: true
  configs:
    cpa-manager-plus:
      enabled: true
      priority: 10
      manager_base_url: "http://127.0.0.1:18317"
      # management_key: "optional-plus-manager-admin-key"
```

Restart CPA after installing or upgrading; already loaded dynamic libraries are not hot-swapped.

## Runtime prerequisites

1. CPA plugins are enabled.
2. Manager Server is running and listening on `manager_base_url`.
3. The CPA management UI is logged in, or the CPA management key is entered temporarily on the plugin page.
4. If Manager Server uses an admin key, set `management_key` in plugin config.

## Verification

```bash
cd plugins/cpa-manager-plus
make build
cd go
go test ./...
go vet ./...
nm ../cpa-manager-plus-v0.3.8.dylib | grep cliproxy_plugin_init
```

Also check:

- `go/web-dist/index.html` references `./assets/app.js` and `./assets/app.css`.
- Dynamic library strings contain `./assets/app.js`, `./assets/app.css`, and business API markers.
- Exported symbols include `cliproxy_plugin_init`, `cliproxyPluginCall`, and `cliproxyPluginFree`.
- The zip contains only the platform dynamic library.

## Non-goals

- Do not fully recreate every complex interaction from the original Plus React pages.
- Do not inline Manager Server backend modules.
- Do not provide a generic HTTP tunnel.
