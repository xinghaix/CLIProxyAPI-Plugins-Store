# CPA Manager Plus (CPA Plugin)

[中文](README.md) | English

`cpa-manager-plus` adds a sidebar menu item named "CPA Manager Plus" to the CPA management UI. The page uses tabs for dashboard, usage analytics, request monitoring, account inspection, settings, and health checks.

Starting with **0.4.0**, the plugin runs an in-process **local Runtime** (SQLite + workers) inside CPA. It **no longer depends on an external Manager Server or reverse proxy to `:18317`**.

## Current architecture decision

This plugin does not proxy, iframe, or embed the full legacy Plus `management.html` page, and external Manager is no longer a runtime prerequisite.

Correct boundary:

1. The frontend belongs to the plugin
   - The plugin resource page is a CPA-style single-page app.
   - Tabs: overview, usage analytics, request monitoring, auth exceptions, account inspection, settings, and health.
   - Styling uses CPA Management Center CSS variables.

2. Backend capabilities live in the plugin local Runtime
   - SQLite, usage ingest, rollups, Codex inspection, and account-action handling run in-process.
   - Default data dir is CWD-relative for development; production should set an absolute `data_dir`.

3. The browser only talks to same-origin CPA management APIs
   - Browser → `POST /v0/management/cpa-manager-plus/api` (payload shape compatible with the old proxy)
   - Browser → `GET /v0/management/cpa-manager-plus/health`
   - The plugin dispatches locally; this is not a generic HTTP tunnel.

## URL structure

| Feature | Path | Notes |
|---------|------|-------|
| Plugin page | `GET /v0/resource/plugins/cpa-manager-plus/app` | Resource route, no CPA management middleware |
| Health check | `GET /v0/management/cpa-manager-plus/health` | CPA management auth; local Runtime status |
| API gateway | `POST /v0/management/cpa-manager-plus/api` | CPA management auth; local dispatch (proxy-compatible payload) |

API request body (still sent by frontend `proxyCall`):

```json
{
  "method": "GET",
  "path": "/v0/management/dashboard/summary",
  "query": "today_start_ms=1710000000000"
}
```

`path` is a local Runtime business path. The plugin validates both path and method through an allowlist.

## Primary local APIs (allowlist)

- `/health`, `/status`
- `/usage-service/config`
- `/v0/management/dashboard/summary`
- `/v0/management/model-prices`
- `/v0/management/monitoring/analytics`
- `/v0/management/codex-inspection/run|runs|...`
- `/v0/management/account-action-candidates` and `.../enable|ignore|resolve|auth-file`

## Local credential health inspection

Starting with **0.5.0**, account inspection runs real provider probes inside the plugin local Runtime instead of only summarizing auth-file status.

- Supports **Codex**, **xAI**, and the combined **Codex + xAI** selection with per-provider sampling.
- Uses CPA management `api-call` with `auth_index`; authentication tokens are never written to plugin SQLite, inspection logs, or browser responses.
- Codex uses a usage probe. xAI uses billing probes and can optionally perform an inference health probe.
- Supports schedules, manual starts, cancellation, persisted result logs, quota thresholds, and controlled automatic actions.
- Automatic recovery only re-enables credentials that this inspection automatically disabled and recorded as owned. Invalid credentials, rate limits, protocol changes, and missing auth metadata remain manual-review outcomes.

Real inspection requires the CPA management address and key in **Account action authorization**, and a target CPA that supports `/v0/management/api-call`. Start with automatic actions disabled to confirm provider responses and result classification before enabling actions.

## Configuration: `plugins.configs.cpa-manager-plus`

| Field | Description |
|-------|-------------|
| `enabled` | Enable the plugin |
| `data_dir` | Local SQLite / data.key directory; absolute path strongly recommended in production |
| `db_filename` | Optional, default `manager.sqlite` |
| `ingest_mode` | Optional: `usage_plugin` (default) / `queue` / `dual` |
| `egress_proxy_url` | Optional outbound proxy for external price sync only |

Deprecated (ignored when present): `manager_base_url`, `management_key` (legacy Plus admin), Manager-facing `proxy_url`.

Browser access to `/v0/management/cpa-manager-plus/*` still needs the CPA `remote-management.secret-key` (management login or temporary key on the config tab). The plugin may also store a CPA connection key in SQLite for host management/auth calls; that key is separate from the browser key.

Example:

```yaml
plugins:
  enabled: true
  configs:
    cpa-manager-plus:
      enabled: true
      priority: 10
      data_dir: "/var/lib/cliproxyapi/plugins/cpa-manager-plus"
      # ingest_mode: "usage_plugin"
```

## Installation

### Recommended: CPA v7.2.46+ with CDN v2 registry

> **CPA Manager Plus requires CPA v7.2.103+.** v7.2.46+ here only indicates registry-v2 installation support; earlier CPA versions cannot load this plugin.

```yaml
plugins:
  enabled: true
  store-sources:
    - "https://cdn.jsdelivr.net/gh/xinghaix/CLIProxyAPI-Plugins-Store@cdn/registry-v2.json"
```

### GitHub raw fallback

```yaml
plugins:
  enabled: true
  store-sources:
    - "https://raw.githubusercontent.com/xinghaix/CLIProxyAPI-Plugins-Store/main/registry-v2.json"
```

### Older CPA compatibility entry point

```yaml
plugins:
  enabled: true
  store-sources:
    - "https://raw.githubusercontent.com/xinghaix/CLIProxyAPI-Plugins-Store/main/registry.json"
```

Install:

```bash
curl -X POST http://localhost:8317/v0/management/plugin-store/cpa-manager-plus/install \
  -H "Authorization: Bearer ***"
```

Restart CPA after installing or upgrading; already loaded dynamic libraries are not hot-swapped.

## Runtime prerequisites

1. CPA plugins are enabled.
2. **No** external Manager Server / `:18317` is required.
3. The CPA management UI is logged in, or the CPA management key is entered temporarily on the plugin page.
4. Production should set an explicit `data_dir`.
5. Local mode owns the host CPA usage stream; do not run the legacy external Manager against the same `usage-queue`.

## Non-goals

- Do not fully recreate every complex interaction from the original Plus React pages.
- Do not provide a generic HTTP tunnel.
- Do not turn the plugin into a standalone network service.
- Do not auto-import historical databases from the external Manager.
